## 1. 分支策略（关键）

**不开独立分支**。两分叉会话共享同一工作目录 `<repo_root>`，切分支会连带切走对方的工作树。约定：

- 两会话都在 `v2` 上直接 commit；
- **提交前必须 `git pull --rebase origin v2`**（吸收对方新提交）；
- **commit 必须路径限定**：`git commit -- <自己的路径列表>`，禁止无路径裸 commit——两会话共享 git index，裸提交会扫入对方已暂存内容（2026-10-06 实测发生：`8519149` 扫入分叉会话 4 个 O-Day 10 文件，内容完整仅归属信息错位，不回滚）；
- **文件域硬隔离**（见 §2），越界前必须在各自会话里停下来确认；
- Cargo.lock 允许双方变更（合并即叠加依赖），拉取后若 `cargo check` 失败先跑 `cargo update -p <crate>` 或直接重新 build。

## 3. Rust 侧纪律（分叉会话特别约束）

- **唯一决策真源**：bench 层只组装输入调用 `orchestrator.rs`/`router.rs` 现有公开函数，**禁止复制核心逻辑**（RouterBench parity 先例：`crates/lloom-core/src/bench.rs` 是样板）；
- 生产接口不适合测试时：加纯函数/trait/test seam（`#[cfg(test)]` 或 pub fn 重构），**不改行为**；
- 每次提交前质量门：`cargo clippy --workspace --all-targets -- -D warnings` + `cargo test --workspace` 全绿（基线 135+，分叉会话应只增不减）；
- 新增模块挂 `crates/lloom-core/src/lib.rs` 时注意：**本会话也可能加模块**（RouterBench 侧），rebase 后若冲突，双方约定在 mod 列表按字母序插入即可消解。

## 4. 数据与环境

- **零 API 成本红线**（16-v3 §十八）：分叉会话本阶段禁止任何 LLM/judge 调用，APB online/τ² live/ToolSandbox live 全部后置；
- **大文件进外置盘**：`/Volumes/Files/LLooM-bench/`（AGENTS.md「Bench 数据存储」节有操作 SOP）。PlanningBench/TPS-Bench 下载件若超 ~100MB，同样处理：实体放外置盘 + 仓内 symlink + `.gitignore` 覆盖（symlink 规则不能带尾斜杠，git 视 symlink 为文件）；
- Python 环境可复用 `benchmarks/routerbench/.venv`（pandas/numpy，只读引用），或 `uv venv` 自建于 `benchmarks/orchestration/`；
- **jsonl 读写坑**（Day 6 实测）：JSON 字符串里合法的 U+2028/U+2029 会被 `str.splitlines()` 误切——一律用 `split("\n")`；
- **Mimosa 钩子**：pickle 反序列化（用 sha256 前置校验+白名单 Unpickler）、`random` 模块（用哈希桶）、路径拼接与硬编码密钥形状都会拦——参考 `benchmarks/routerbench/scripts/import_frozen.py` 的通过写法；被拦时改写候选本身。

2. 产出**交接报告**（建议落 `research/手记规划-20260928/`，编号见该目录现有序号顺延），含：产出清单、Gate 对照（O-0~O-5 各到什么程度）、诚实边界、下一步建议；
