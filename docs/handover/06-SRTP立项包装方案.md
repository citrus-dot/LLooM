## 三、创新点提炼（打实「评分系统」等四条）

> 每条给：卖点句 → 已有工程基础 → 还需补什么 → 证据强度。主次关系见 00 §七 D2（推荐 a 主 + b/c 辅）。

### 创新点 1（主）：缓存感知的成本-质量联合路由优化

- **卖点句**：现有缓存感知调度（NVIDIA Dynamo、llm-d、SageMaker 前缀路由）都在**同一模型的多个副本间**做前缀亲和；本文在 **API 网关层跨模型选择**中引入缓存协同——把「切换模型导致供应商侧缓存失效的损失」用真实计价（p_in − p_read）× 前缀长度 × (1−ĥ) 折算进选择目标，实现质量、账单成本、缓存命中的联合优化；并给出显式/隐式缓存的自动选择判据（增量不足前缀 40% 时打显式缓存标更省，由官方计价数字推导）。**该问题在 API 网关语境未见直接先例**（FATE/Cascadia 等先例在集群调度/级联语境，related work 已成表）。计价链路的正确性有「口径不变量 + 运行时断言」保障（07 §一），这也是系统可靠性的可讲素材。
- **已有基础**：三档缓存计价引擎（`pricing.rs:441-452`）、cached_tokens 全链路落库、task 级命中率 EWMA 喂 `est_cost`（`router.rs:588-598`）、会话粘性 bonus（B15）、供应商计价矩阵实测（01 §三.1）。
- **还需补**：01 方案 C1-C5（会话级 ĥ、前视 SL 项、write 摊销、TTL 门）——第二梯队 3-4 周。
- **证据强度**：★★★（机制过半已落地；空白点有行业+学术双侧检索支撑）。

### 创新点 2（手记点名）：校准式多维评分系统

- **卖点句**：路由评分不是拍脑袋权重，而是**「信号 → 校准预测 → 多维评分」的闭环体系**：质量预测带 Brier/ECE 校准与可靠性图、成本预测带缓存命中率期望加权、可用性来自健康状态机与延迟 EWMA，所有预测分量在留出集上报告校准指标——把「预测错误不会被优化器修复」这一路由领域核心教训（OmniRouter/最终版 §三）变成工程约束。
- **已有基础**：`quality_override` 注入通道、L1-L4 标签分级、EWMA 体系、health.rs、影子评测与配对验收协议。
- **还需补**：02 方案 Q1-Q3（本地 oracle 数据集、isotonic 校准层、Brier/ECE 报告）+ C10 propensity 快照。
- **证据强度**：★★★（方法论全部有出处，工程项第二梯队可完成）。

### 创新点 3（辅）：零训练的运行时路由（投机比较 + 经验包缓存）

- **卖点句**：不训练预测器，用运行时信号决定执行权——小/强模型各出结构化行动提案比较分配 + 强模型已验证经验作为小模型 RAG 上下文（IC-Cache 方向证据：吞吐 1.4-5.9×）；全程不改推理引擎、不要求 token 概率，纯 API 层可实现。
- **已有基础**：完整设计已论证（最终版方向四，权威文档级）+ 影子多跑第三臂的提案级变体方案 + `router_history` collection 底座。
- **还需补**：MVP 四段落地（经验包 → 提案比较 → 额度校准 → 嵌套资格），P2 起分四段；**申报书里作为路线图呈现，不承诺全部完成**。
- **证据强度**：★★（设计充分、实证未启动——写成"部分实现+完整路线"最稳）。

### 创新点 4（探索点）：行为风格画像驱动的路由特征

- **卖点句**：将心理测量学方法引入模型选择：新模型入网时跑四特征行为画像（啰嗦度/谄媚度/风险偏好/校准度），作为路由辅助特征——「LLM 心理测量→路由决策」在文献中为空白（04 §四检索结论）。
- **已有基础**：入网七步流程设计、metadata.rs 打标机制、`behavior` 画像字段预留。
- **还需补**：B18 探测集构建（10-20 题 × 4 特征）+ 小规模相关性验证（画像特征 vs 实际任务表现）。
- **证据强度**：★★（新颖性高但需引用反方 Personality Without Persons 控制表述——全部用「行为风格统计量」，不用「人格」）。
- **用途建议**：作为第四创新点或"拓展研究"呈现，不扛主叙事。

## 四、理论上升叙事（对应手记「强化学习/…」）

> 完整形式化在 03 §二/§五，此处只给**申报书可直接使用的表述层级**。

| 层级 | 申报书表述 | 状态 |
|---|---|---|
| 形式化 | 将路由建模为**带切换成本的约束上下文 bandit**（质量约束 + 预算 knapsack + 供应商容量），通过**拉格朗日对偶**将约束转化为在线更新的对偶价格（预算 λ₁ / 容量 λ₂ⱼ / 缓存一致性 μ），请求级评分即其对偶贪心解 | 03 §二.1 映射表：每个数学对象 ↔ 现有代码锚点一一对应 |
| 学习理论定位 | 系统面临**部分反馈**（只见被选模型的结果）；为此记录候选集与选择概率（propensity），支持 **doubly robust 反事实评估**与离线策略评估——这是数据型创新点，评审可验证 | C10 是前置，P0 落地 |
| 强化学习（诚实版） | 端到端 RL 路由设**明确触发条件**（影子样本达千级）；触发后先做离线回放评估与保守策略改进，不做端到端训练。写成「演进路线」而非承诺——**反例预警**：宣称做 RL 但数据只有几百条是答辩最容易被击穿的点 | B10 台账条件不变 |

**一句话版本（摘要用）**："本系统将多模型路由形式化为带切换成本的约束上下文 bandit，以对偶价格与置信半径实现可解释的贪心近似，并通过倾向日志支撑离线策略评估；强化学习式策略改进作为数据规模达标后的演进路线。"

## 六、申报书「写法改进」与「项目理解」：材料维度

### 6.1 题目候选（按主创新点排序）

1. **《面向多供应商大模型的缓存感知成本-质量联合路由网关》（推荐）**——直接命中创新点 1，"缓存感知"是与 RouteLLM 类工作的差异词；
2. 《基于校准评分体系的多模型智能路由系统设计与实现》——偏"评分系统"（手记点名），稳妥但创新锐度略低；
3. 《LLM 路由网关中的缓存-路由协同优化方法研究》——偏研究型表述，适合论文后来居上时改投。

### 6.2 摘要骨架（150-200 字模板）

> 背景：多供应商 LLM API 并存，选模面临质量-成本权衡（1 句）→ 痛点：现有工作忽视「跨模型切换导致 prompt 缓存失效」的隐性成本（1 句，引 01 §三空白点）→ 方法：形式化为带切换成本的约束优化，对偶价格 + 校准质量预测 + 会话级命中率估计（2 句）→ 结果：系统已实现并发布，影子评测显示在质量不降前提下账单成本下降 X%（X 用真实影子数据填，**不写估计值**）→ 意义：可解释、可回退、可复现（1 句）。

### 6.3 创新点表述句式（「打实」的具体手法）

- **差写法**（会被追问到死）："采用强化学习实现智能路由" / "使用评分系统进行智能选择"。
- **好写法**（每句可落地）："将预算约束转化为在线更新的对偶价格 λ，替代固定预算倍率（控制论闭环验证收敛性）" / "质量预测分量强制报告 Brier 分数与 ECE，未校准不上线" / "以会话级缓存命中率估计将切换损失折算为真实价差计入评分"。
- 通用规则：**每个"智能"都换成一个数学对象 + 一个验收指标**；数字只用实测（影子数据/AIQ 曲线），不用行业外推。

### 6.4 「项目理解」：答辩常见质疑与预案

| 预期质疑 | 预案（材料里预埋 + 口头应对） |
|---|---|
| "单用户数据量太小，凭什么训练/评估？" | ① 方法评估走公开集（RouterBench 405k）离线验证；② 系统评估用影子双跑 + 配对统计（bootstrap CI）；③ propensity 日志使反事实评估不依赖 A/B。三层递进，每一层都不需要海量自有数据 |
| "与 RouteLLM/OpenRouter 有何区别？" | ① RouteLLM 是模型间路由研究框架，无缓存/预算/计价工程闭环；OpenRouter auto 是黑盒商业策略。LLooM 开源、可解释、且**缓存协同是两者都没有的维度**（01 §三.2 空白表） |
| "学习型路由已被证明收益有限（平台期），你们的意义？" | 正面引用 Routing Plateau/LLMRouterBench：平台期存在于"纯学习型路由"；本文收益主要来自**缓存协同与预算控制**（非学习组件），学习分量设三重闸门——这恰是"知道边界在哪"的表现 |
| "评分权重是不是调出来的？" | 逐项回答：λ 对偶更新（非手调）、UCB 置信半径（非 −0.3 罚分）、SL 真实价差（非 cap 0.25）——每个替换都对应一次"手调 → 原则量"的升级，这正是 03 §二.1 的映射表 |
| "可靠性怎么保证？" | 影子先行 ≥2 周、settings 三态开关一键回退、硬门槛不参与优化、缓存回归检查——把工程纪律本身讲成可靠性设计 |
