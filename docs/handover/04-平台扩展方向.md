## 二、智能体互联协同：协议现状与 LLooM 的三种姿态

### 2.1 协议现状（2026-09 时点，A 级）

| 协议 | 状态 | 一句话 |
|---|---|---|
| MCP（Anthropic） | **事实标准**，行业快速采用（OpenAI/Google 等均支持） | Agent ↔ 工具/数据/上下文的「设备驱动」层 |
| A2A（Agent2Agent） | 2025-04 Google 发布（50+ 伙伴）→ 2025-06 捐赠 **Linux Foundation**（Apache 2.0）→ **2026-03-12 发布 v1.0 稳定规范** → 2026-04 宣布 150+ 成员组织；采用节奏慢于 MCP 但 2026 年进入云平台与企业生产 | Agent ↔ Agent 的任务委托/发现/协商层 |
| 共识定位 | 「**A2A orchestrates the team; MCP equips each agent**」——互补不竞争 | LLooM 两层都可以挂 |

### 2.2 LLooM 的三种姿态对比（决策点，供拍板）

| 姿态 | 机制 | 复用 LLooM 什么 | 成本 | 价值 | 建议 |
|---|---|---|---|---|---|
| a) MCP **server** | 把路由/缓存/定价/用量暴露为 MCP 工具 | 全部核心能力零改造 | 低（FastAPI 或 Rust 侧挂 MCP 端点） | 让任意 MCP 客户端（Claude Code 等）消费 LLooM 的路由决策与成本核算 | **推荐先做**（台账 B4 原语义，G2 触发即做） |
| b) Agent 流量**感知网关** | 识别 /v1 上的 agent 循环流量（tool_call 轨迹信号），做任务级粘性、agent 预算分桶、终局奖励统计 | C4' 轨迹信号设计（最终版 §四）+ D3 session_key | 中 | agent 是未来主力流量；任务级粘性在 agent 场景收益最大（TRACE-Router 证据：任务级绑定优于逐调用） | 第二步（依赖 C6 会话键落地） |
| c) A2A 消费/路由 | LLooM 作为 agent 编排器间的一跳（按 A2A task 语义计费与粘性） | b 的全部 + A2A 语义映射 | 高 | 赛道前瞻，暂无真实流量 | 远期占位，不做 |

**推荐路径**：a → b，触发门维持 B4/G2（「出现外部智能体要消费 LLooM」）。注意 b 的前置（session_key、决策快照）恰好都是 01/05 方案的第一二梯队项——**平台方向与主线共享地基，不冲突**。

## 三、云端预处理与 PD 分离：认知层价值 + 一个可落地的「preflight 层」

### 3.1 PD 分离是什么（背景调研）

- **Prefill（预填充）**：处理输入 prompt、计算密集、产出 KV cache；**Decode（解码）**：逐 token 生成、访存密集。两者资源画像相反，混部互相干扰。
- 分离（P/D disaggregation）把两阶段放到不同资源池，KV cache 跨节点传输。代表系统：**DistServe（OSDI 2024，goodput 目标）、Splitwise（ISCA 2024）、Mooncake（KV cache 中心架构，FAST 2025）**；2025-2026 已进入主流引擎（vLLM、SGLang 均有 PD 分离部署模式，另有 Janus 等联合优化工作）。**DeepSeek 服务端即按此架构运行**。
- 对 API 用户（LLooM 的处境）的影响：这就是「为什么各家 prompt cache 计价规则差异那么大」的架构根源——缓存价（read）、写溢价（write）、TTL 全由服务端缓存基础设施决定，客户端不可控。

### 3.2 对 LLooM 的三重含义

1. **认知层（现在就有用）**：01 §三的计价矩阵差异（OpenAI 无写溢价 vs Anthropic 1.25×/2×）本质是各家缓存基础设施与 PD 架构不同——理解这一点，`price_specs` 的 `cache_read/write_cost` 双档设计才不是过度设计，而是必要建模。
2. **自建推理远期选项（G1/D5 门后）**：若未来自建 vLLM（而非 Ollama），PD 分离 + prefix-hash 亲和（台账 D5）才实体化；当前 Ollama 单机语境下**不可达也不必达**。
3. **「云端预处理」可落地版：preflight 预处理层（B17，P2/条件触发）**——LLooM 自己的「Prefill 前置阶段」：

```text
请求 → [preflight：轻模型/本地模型处理] → 主路由 → 主模型
         ├ 上下文预压缩（长 history 摘要替换，配合 CONTEXT_BUDGET=24000）
         ├ 工具结果/检索结果摘要化（喂给主模型前先压缩）
         ├ PII 清洗（security.rs 已有检测，前置复用）
         └ 用户记忆检索注入（02 Q6 的读取点）
```

  - **经济学**：preflight 用本地 Ollama 或最便宜云端模型跑，成本趋近 0；换来主模型输入 token 下降（直接省 p_in）与命中率提升（压缩后前缀更稳定）。
  - **压缩文献支撑（第二轮补，07 §三.3）**：LLMLingua/LLMLingua-2 词级压缩最高 ~20×；抽象式压缩（定期 LLM 摘要长历史）与 LLooM 已有 rolling summary **完全同构**——2026 年业界已把「caching + compression」并列为两大成本杠杆，LLooM 的 preflight 第一版就是**rolling summary 前移 + 工具结果摘要化（零新依赖）**，LLMLingua 类压缩模型留作升级选项；代码场景有直接证据（SWEzze：每实例省 ~13k prompt token）。
  - **风险**：压缩失真损质量——必须配 02 的 L1/L2 标签做配对验收，压缩仅在超阈值会话启用（触发条件：长上下文流量占比可观测后，即 B17 解锁条件）。
  - **与手记「云端预处理 pd分离」的对应**：手记直觉是对的——LLooM 能做的是「网关侧的 prefill 前置」，引擎级 PD 分离是 provider 的事（认知）+ 自建时的事（远期）。

## 四、模型心理测试：从「能力画像」到「心理画像」

### 4.1 领域调研（2026-09 时点）

| 工作 | 内容 | 对 LLooM 的可用性 |
|---|---|---|
| **LLM Psychometrics 系统综述**（arXiv:2505.08245，llm-psychometrics.com） | 用心理测量学方法（信度/效度/因子分析）系统评测 LLM 的人格与认知构造 | 方法论框架来源 |
| **PsyEval**（arXiv:2406.17675） | 心理测量基准：人格/价值观/情绪/心智理论等六维 | 探测题库参考 |
| **TRAIT**（arXiv:2406.14703） | 八特质人格测评（Dark Triad + Big Five），强调区分度与一致性 | 问卷范式参考 |
| Serapio-García et al., **Nature Machine Intelligence 2025** | 心理测量的人格分数能稳健预测下游任务行为 | **「心理特征→任务表现」可用性的最强支撑** |
| **Personality Without Persons?**（arXiv:2607.02325） | 批判：Big Five 分数在 LLM 上不构成与人类人格等效的构念 | **必须引用的反方**——防止过度拟人化叙事 |
| RADAR（ICLR 2026）/ Model-SAT（AAAI 2025） | Fisher 信息自适应出题 / aptitude test（50 类 × 20-shot 生成能力描述） | **能力维度「心理测试」的既有设计**（最终版方向一已收录） |

**关键判断**：① 能力维度的「心理测试」已是成熟路线（IRT/自适应测验），LLooM 新模型入网七步（最终版 §2.2：模型卡先验 → 代表题粗测 → 高信息题补测 → 留出校准 → 影子 → 小比例随机 → 扩大）**就是它的工程化**，无需另起炉灶；② **「心理/风格特征 → 路由决策」没有直接文献**（检索确认空白）——这既是 SRTP 新颖性机会（06 §三），也是构念效度风险区。

### 4.2 LLooM 落地设计（B18，P2，条件触发 = SRTP 立项或新模型入网频繁）

- **风格画像四特征探测集**（每特征 10-20 题，新模型入网时一次跑完，成本 < $1）：

| 特征 | 探测方式 | 路由用途 |
|---|---|---|
| 啰嗦度 verbosity | 固定问题集测输出长度分布 | 与 est_out 长度预测耦合（01 C4）；延迟敏感场景降权 |
| 谄媚度 sycophancy | **三场景分层探测**（07 §三.4 修订）：①观点附和（SycophancyEval QnA 范式，arXiv:2310.13548：用户先表达可能错误观点再提问）②事实纠错 ③代码确认；各 5-8 题。跨模型区分度有实证（PSRS 率 5%-56%，越强越不谄媚） | 高风险任务（代写代码/事实判断）屏蔽高谄媚模型 |
| 风险偏好 risk | 模糊需求下是否擅自假设/行动 | agent 编排路径的提案激进程度先验 |
| 校准度 calibration | 让模型自报置信度，与实际对错对比（Brier） | 「置信下界」评分项的 per-model 修正 |

- **工程落点**：`metadata.rs` 五级打标的扩展（capability 之外加 profile 维度）；探测结果进模型 YAML schema（最终版 §2.2 的画像 schema 已预留 `behavior` 字段）。
- **诚实边界**：四特征全部标注为「行为风格统计量」，**不使用「人格」表述**（引用 Personality Without Persons 反方）；只作辅助特征，主评分仍是质量/成本/缓存三项。

## 五、Switchyard 加入评估（手记 #19）

- **2026-09-28 复核结论**：NVIDIA-NeMo/Switchyard README 自述仍为 **pre-alpha**（"API and algorithms are expected to change significantly before we reach v1.0"，not for production use）；当前 tag v0.2.0（libsy 生态）。**台账 B11「等 v1.0 且走 libsy 库路径」维持不变，判定依据未变。**

## 六、多模态？（范围裁定）

- **现状盘点**：`validate_messages` 已放行多模态分段数组（2026-09-18 边缘加固时的有意设计）；models 表有 capability_tier（1-3 能力档）但**无模态字段**；`price_specs` 是纯文本 token 维度（图像 token 计价规则不同：OpenAI 按 tile、Anthropic ≈ (w×h)/750）；litellm 支持视觉模型透传。
- **裁定建议（00 §七 D3）**：本期不做，维持 B6「G1 之后」。理由：无真实多模态流量、图像计价与能力矩阵工作量大、litellm 图像 usage 归一化字段需专项验证——投入产出比显著低于 01/02。
- **若触发，最小路径**（预留设计，约 3-5 天）：① `models` 表加 `modalities` JSON 字段（`{"image_input": true, "audio_input": false, ...}`），metadata.rs 自动回填启发式（模型名/家族）；② 路由门槛：请求含 image 分段 → 过滤 `image_input=false` 模型（**门槛层，不是评分层**——模态不匹配是硬失败，符合「不动门槛只动评分」的例外逻辑：这属于「注册表门槛」语义）；③ 定价：price_specs 加图像单价档（per-image 或 per-tile 换算成 USD/image），est_cost 对图像分段按张数估算。

## 八、触发后 72 小时开工包（台账触发即拿即用，避免「条件到了不知道从哪下手」）

### B4 MCP server（G2 触发）

1. 工具清单定稿（4 个，直接映射现有 REST 能力）：`lloom_route`（入参 query/band → 出参候选+评分）/ `lloom_cost_estimate`（入参 messages+model → est_cost）/ `lloom_usage_report`（时间窗 → 用量分列）/ `lloom_cache_stats`（命中率+saved_cost）；
2. 传输选型：CLI 场景 stdio / 远程场景 SSE——挂 FastAPI（:7862）或 Rust 侧二选一，**先 stdio 后 SSE**（依赖最少）；
3. 鉴权复用 `proxy_token`（settings KV 语义现成）；
4. 冒烟：任一 MCP 客户端跑通 `lloom_route` 单工具即达标。

### B17 preflight 预处理层（长上下文可观测触发）

1. 观测先行：`metrics.rs`（N3.b 框架）加 `lloom_context_tokens` 直方图；
2. 触发阈值定量化：**p90 context_tokens > 18000（= 24k 预算的 75%）连续 7 天** → 开工；
3. MVP 锁定范围：rolling summary 前移 + 工具结果摘要化（零新依赖，07 §三.3 结论），压缩模型（LLMLingua 类）不进第一版；
4. 验收：开启前后同会话配对——主模型输入 token 下降 ≥25% 且 L1 结构化成功率不降。

### B18 心理画像探测集（SRTP 立项或入网频繁触发）

1. 探测集 v0 = 4 特征 × 6 题（全公开范式改造）：谄媚度用 SycophancyEval QnA 范式 6 题（三场景各 2）、啰嗦度指令跟随 6 题、风险偏好模糊任务 6 题、校准度自报置信 6 题；
2. 计分脚本：模型响应 JSONL → 四特征分（0-1），输出进 `metadata.rs` behavior 字段（schema 预留位）；
3. 成本护栏：单模型全测 < $1（每题 ≤1k token，按现注册价目核）；
4. 表述纪律：全部称「行为风格统计量」，不称「人格」（Personality Without Persons 反方约束）。
