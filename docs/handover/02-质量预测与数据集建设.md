## 一、定位：这条线解决「预测错误不被优化器修复」的问题

最终版方向二的核心论断：「**预测错误不会被优化器修复**——把 0.50 错估成 0.90，任何预算优化都会把更多流量给它」。所以手记这条线（oracle 数据集 → 质量预测 → 校准评分）是 01/03 两份方案的**上游燃料**：路由评分里每一项（`P̂(ok|q,m)`、est_out、ĥ）的精度上限都由数据与校准决定。

三个已有设计结论直接继承（最终版 §2.1-2.2，此处仅引用）：

1. 标签分级 L1 结构化判定 / L2 用户反馈 / L3 影子 judge 可入训练；**L4 回填永不入训练集与 hold-out**；
2. Oracle 有两种（hindsight sample vs expected-quality policy），**hindsight oracle gap 含采样随机性，不全是可学习空间**——数据集建设时必须记录 oracle 类型；
3. 学习路由有平台期证据（LLMRouterBench / Routing Plateau：复杂路由器 ≈ kNN，最佳仍落后 Oracle 10-30pp）→ **V1 双头预测器设三重闸门（可信标签 ≥1500 + 每 query 覆盖 ≥3 模型 + 离线基线全败含 RadialRouter 复现），闸门不过不训练**。

## 三、公开数据集调研（手记：`[分两维度找数据集]`）

「分两维度」的最自然解读：路由数据集的本质是 **(质量， 成本) 二维平面上的散点**，选模型 = 在这个平面上找前沿（RouterBench 的 AIQ/NDCH 指标就是「共同成本区间内非递减凸包面积」）。下表按「能否支撑两维评测」整理公开集：

| 数据集 | 规模 | 质量维 | 成本维 | 获取状态 | 对 LLooM 的用途 |
|---|---|---|---|---|---|
| RouterBench（Martian/UCB/UCSD, arXiv:2403.12031） | 405,467 = 11 模型 × 8 数据集 | 每格 (query, model) 有对错标签 | 每格有 token 计费成本 | 代码与数据公开（2024 预印本） | **主力离线验证集**：复现 kNN/Zero Router 基线、AIQ 曲线 |
| LLMRouterBench（ACL 2026 Findings, arXiv:2601.07206） | 33 模型 × 21 数据集 × 40 万+ | 同上 | 同上 | **HF 可下载**：`ynulihao/LLMRouterBench`（多源一致确认，B+ 级；受限网络走 hf-mirror，Q2 开工时验证） | 平台期复核 + model recall 指标复用 |
| RouteLLM 训练数据（LMSYS, ICLR 2025） | Chatbot Arena 衍生 | 偏好对（非对错） | 有 | 公开 | 偏好式标签的补充形态，暂不主用 |
| lmsys-chat-1m | 100 万真实对话 | 无模型对标签 | — | 公开 | 真实查询分布参考、任务分类语料 |
| TRACE-Router 基准（τ²-Bench / LiveCodeBench / Terminal-Bench） | agent 任务级 | 终局结果 | token 计费 | 各基准公开 | 方向三任务级路由评测（远期） |
| **本地数据集（本方案 Q1 产出）** | 单用户量级（≥300 可信样本 ≈ 60-100 天流量） | L1-L4 标签 | act_cost 真实对账 | 自建 | **领域分布匹配的唯一来源**；公开集做广度、本地集做校准 |

**使用原则（继承最终版评测协议）**：公开集负责「离线验证方法不劣于基线」（五种切分、七基线、Brier/ECE），本地集负责「上线前的领域校准与影子对照」；两边的 Oracle 类型都必须显式标注。

## 四、方案设计（Q1-Q7）

### Q1 本地 oracle 数据集建设（P0，对应台账 A1 数据导出）

- **形态**：一行 = `(query_id, model_name, task_type, label_level, label, est_cost, act_cost, latency_ms, ts, oracle_type, policy_version)`。
- **来源三张表**：`usage_records`（token/成本/延迟/cached_tokens）× `routing_decisions`（快照，**依赖 05 §五 C10 补 propensity 字段**）× `conversations`（query 文本）。
- **导出脚本**：`scripts/export_routerbench_local.py`（只读 lloom.db，输出 parquet/JSONL；不碰 Python 侧 ChromaDB）。
- **规模预期管理**：单用户流量下 ≥300 可信样本 ≈ 60-100 天（最终版结论），**工程周期与数据闸门 wall-clock 分列**，不做假数据。

### Q2 离线验证协议（P1）

- 五种切分（随机/语义簇/时间/新模型留出/Agent 完整任务）+ 七基线（Cheapest/Best Single/Category Best/固定随机/kNN/当前 LLooM 规则/Oracle 上界）+ 必报指标（AIQ、model recall、hard-query recall、Brier+ECE、p50/p95/p99、预算违反率）——**全套沿用最终版 §八**，不另行发明。
- 复用既有工具：`aiq_replay.py` 多曲线对比已有。

### Q3 质量预测模型路线（P2→P3，闸门驱动）

- **V0 检索评分（P2）**：query embedding 检索 K 近邻历史样本 → (model,task) 检索均值 → **isotonic/分位映射校准层**（论文能力分数是成功概率尺度，≠ ewma_quality 尺度）→ `quality_override` 注入。<3 条相似样本回落 EWMA。
- **V1 双头预测器（P3，不排期）**：能力头 + 输出长度桶头（OmniRouter 形态）；三重闸门 + RadialRouter 复现基线 + Brier/ECE 校准硬门槛。
- **est_out 报分位数而非均值（第二轮补，07 §三.1）**：输出长度分布重尾（arXiv:2604.00499 的核心论点），KNN 检索值报 P50/P90 两档——成本预估用 P50（期望账单）、风险口径用 P90（超支概率），比单一 MAPE 更贴路由用途；长度桶粒度影响路由性能（OmniRouter 结论）支持分桶而非回归。
- **「基于预测/检索」的手记语义**即此路线：检索先行零训练、预测器后置闸门。

### Q4 可用性/成本评分（P1）＋「分布式?」裁定

- **补三件事**：① 延迟 EWMA 接线（`router.rs:511` 死代码复活，数据列已就绪 `db.rs:90/224`）；② λ₂ⱼ 限流退避（429 滑窗计数 + 惩罚表，P2 项）；③ 健康状态与评分联动复核（protect 档不动，只动软评分）。
- **「分布式?」的明确回答：不需要，也不建议**。理由：① 评分函数是无状态纯函数（输入信号集 → 输出分数），未来真要多实例，水平扩展的前提是状态外置，而状态外置是 B3 多租户（SQLite→PG）的事——**单机语义下引入分布式评分是负收益**；② 手记该行的语境是 SRTP 展示——「评分体系」作为创新点不需要分布式来撑，需要的是**校准与可解释**（Brier/ECE、可靠性图），这恰恰是单机能做好的。

### Q5 上下文反馈（P1）

- **机制**：会话内三个即时信号回灌**同会话**后续路由评分（区别于全局 EWMA 的慢信号）：① reask（重问 = 上答不满，signals 已捕获）；② escalation/降档事件；③ L1 结构化失败（json 解析失败/工具调用报错）。实现为会话级临时惩罚表（`session_key × model → penalty`，TTL=会话生命周期，内存即可），score_all 读取。
- **与 C2（切换代价）的关系**：反馈惩罚推动「离开表现差的模型」，SL 项阻止「随意离开原模型」——两个力合成自然的**滞回（hysteresis）**行为，避免评分抖动。这是把两个方案串起来的关键设计点。
- **验收**：影子观察会话内连续 2 次同模型失败后的切模率与终局质量。

### Q6 用户记忆模块（P2，MVP 方案，待 D1 拍板）

- **存储**：chroma 新增 `user_memory` collection（与 `lloom_cache` 隔离，embedding 模型同源复用）+ SQLite `user_memory` 表：`(id, kind[fact|preference|event], text, source[explicit|session_end_extract], confidence, created_at, last_hit_at, enabled)`。
- **写入三通道**：① 显式指令（用户说「记住 X」→ 高置信直写）；② 会话结束 LLM 抽取（低频、L2 置信、默认 `enabled=false` 待确认或按 settings 开关）；③ L3 关键事实抽取（**解锁 B14 后复用**，本期不做）。
- **读取**：每轮查询 embedding 检索 top-k（k≤5）+ 时间衰减 + `enabled` 过滤 → 注入 system prompt 尾部（标注来源标记，供调试）。
- **治理**：WebUI 记忆管理页（列表/编辑/删除/禁用）；删除即刻从 SQLite + chroma 双删。
- **边界（红线）**：记忆**只影响 prompt 内容，不进路由评分**——避免记忆命中与质量标签产生混淆变量。
- **与 B14 的关系**：L3 关键事实抽取（摘要之上抽实体/偏好/约束）是记忆抽取的质量升级路径，台账 B14 条件成熟后并入。
- **related work 定位（第二轮补，详见 07 §三.2）**：MVP = 单用户场景的**最小 Mem0 形态**（Mem0 arXiv:2504.19413 的抽取-合并-更新管线是升级路径，其新事实覆盖旧事实的冲突消解优先补）；与 MemoryOS 的「会话 history + 摘要 + 长期记忆」三层结构同构可作设计佐证；A-MEM 的记忆互联、Zep/Letta 属工程服务形态不在本期范围。按 Agent Memory Survey（2025-12）分类法自述：「form=向量库条目，function=用户画像，operation=显式写入+会话末抽取」。

### Q7 设置分类模型（P0，半天，手记 #20 直接兑现）

- **机制**：settings KV 新增 `classifier_model`（空 = 自动 `pick_classifier`，非空 = 强制指定）；WebUI 设置页下拉（仅列 `is_active` 且健康的模型）；`server.rs pick_classifier:2309-2325` 入口读 settings。
- **动机**：分类器自动选「最便宜」可能选到分类质量差的模型（task 判错 → 整条 (model,task) 评分链被污染）；调试时也需要固定分类器排除变量。

### 5.2 Q6 用户记忆落地级（DDL + API + 注入格式）

```sql
CREATE TABLE IF NOT EXISTS user_memory (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    kind TEXT NOT NULL CHECK (kind IN ('fact','preference','event')),
    text TEXT NOT NULL,                -- 抽取后的单句记忆（非原文）
    source TEXT NOT NULL CHECK (source IN ('explicit','session_end')),
    confidence REAL DEFAULT 0.5,
    enabled INTEGER DEFAULT 1,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_hit_at TIMESTAMP
);
```

- **API**：`GET /api/memory`（列表）/ `POST /api/memory`（显式添加，source=explicit, confidence=1.0）/ `PUT /api/memory/{id}`（编辑/禁用）/ `DELETE /api/memory/{id}`（**SQLite + chroma `user_memory` collection 双删**，删除语义与数据不可删边界一致）。
- **注入格式**（`ai_service.py` 装配处，与 rolling summary 分段隔离）：system prompt 尾部追加独立段 `【用户长期记忆（不适用可忽略）】` + 每条 `- {text}`；检索条件 `k≤5 ∧ confidence≥0.5 ∧ enabled=1`，排序权重 = `cosine × exp(−Δdays/90)`（**90 天衰减为 D 级起步参数**，settings `memory_decay_days` 可调）；注入预算 ≤512 tokens，超限截断低权重尾部。
- **写入管线**：显式 = 正则命中「记住/以后/别忘」→ 该轮 user 消息交 `pick_classifier` 同源的轻模型抽**单条**记忆（含原文引用存 `text` 外字段供编辑）；会话末抽取 = settings `session_memory_extract` **默认 off**，开时每会话结束一次 LLM 抽取（confidence=0.5）。
- **红线复述**：记忆只进 prompt，**不进路由评分与训练数据**（避免混淆变量）。

### 5.3 Q3 校准程序 spec（V0 上线的硬程序，缺步不上线）

1. **训练对**：`(检索特征, L1 实际成败)`；检索特征 = k=8 近邻的 cosine 加权均值（**cosine < 0.65 不计入**——参照语义缓存灰区 0.70 阈值先例，D 级起步值）。
2. **校准器**：sklearn `IsotonicRegression`（样本 ≥300 对）；<300 时降级分位映射（quantile mapping）；映射单调性校验。
3. **评估**：时间切分（最近 20% hold-out）→ **Brier 分数 + ECE（10 桶）+ 可靠性图**；gate = hold-out Brier **显著低于同数据全局基线** `p̄(1−p̄)`（p̄=全局成功率——无信息基线；绝对阈值无意义，相对下降才是信号）。
4. **注入**：校准后 `p̂` 经 `quality_override`（键=model_name，`PlanInput` 字段现成 `router.rs:153`）。
5. **回退**：gate 不过 → quality_override 置空回落 EWMA（零行为切换）。

### 5.4 Q7 分类模型配置行为规格

settings `classifier_model`：空 = 自动 `pick_classifier`（现状）；非空 = 强制指定，**指定模型须通过运行时 validate**（is_active ∧ 健康 ≠ down，否则中文报错回落自动选择并告警，不静默吞错）；WebUI 设置页下拉仅列合法候选 + 「自动」项；改动即时生效（settings KV 语义）。

## 七、风险登记

| 风险 | 缓解 |
|---|---|
| 单用户标签量永远不够训 V1 | 三重闸门本来就不承诺训练；V0 检索 + 公开集离线验证已覆盖「方法可行性」叙事 |
| L2 用户反馈噪声大（误点赞） | L2 只按最终版标签分级规则降权使用；关键路径（SRTP 数据集）只用 L1/L3 |
