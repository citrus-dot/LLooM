## 二、统一形式化：把 LLooM 写成一个约束优化问题

### 2.1 目标函数（三份方案文档的合流点）

01 §四的 per-request 选择式是**请求级实例**；把它放进序列决策语境，LLooM 全系统是：

```text
min_π  E[ Σ_t  C(a_t) ]                      ← 长期成本（含缓存切换损失 SL）
s.t.   E[ Σ_t  Q(a_t) ] ≥ Q̄                 ← 质量下界（月度/会话）
       E[ Σ_t  Budget(a_t) ] ≤ B            ← 预算硬约束（budgets 表）
       Capacity_j(a_t) ≤ L_j  ∀j            ← 供应商 RPM/TPM/并发
       硬门槛：protect 档 / 健康 down / max_cost_per_request / context_window 不参与优化（红线）
```

π 即 score_all（`router.rs:477-528`）。**拉格朗日对偶**把四个约束变成四个乘子，评分式里每一项恰好对应一个：

| 约束 | 对偶乘子 | score_all 中现在的形态 | 目标形态（手调 → 原则量） | 依据 |
|---|---|---|---|---|
| 预算 B | λ₁ | `tier_cost_multiplier`（throttle×1.5 / tight×2.5，`router.rs:221-228`，手调阶梯） | 在线对偶更新 `λ₁ ← clamp(λ₁ + η·tanh(e/target), 0, λ_max)`，EMA 平滑（PI 控制器族语义） | OmniRouter 命题 1：`argmin(c − λ₁·a/N + λ₂ⱼ)` 即约束优化最优解（KKT 平稳性；**不保证可行整数解，需可行性恢复**——最终版 §3.1 限定） |
| 质量 Q̄ | （作为正项系数） | `qw·q`（EWMA 点估计） | `p̂ − z·σ̂` 置信下界 + 校准（Brier/ECE）→ 02 方案 Q3 | StageRoute LCB / Routing Plateau 校准结论 |
| 容量 L_j | λ₂ⱼ | 无（429 靠 fallback 兜底） | 滑窗计数 + 惩罚表（P2） | OmniRouter λ₂ⱼ |
| 缓存一致性 | μ | sticky_bonus（后视 cap 0.25） | 前视切换代价 SL（01 方案 C2，真实价差计价） | 本文档 §二.2 |
| 部分反馈/不确定性 | UCB 半径 | 保守期静态罚 −0.3（`router.rs:517`，无原则常数） | `f_rad(v,n)=√(γv/n)+γ/n` + sample_count 30 天窗口化 | StageRoute（公式已逐字核实） |
| 延迟 | λ_lat | `lat` 恒 0 死代码（`router.rs:511`） | EWMA 接线（数据列已就绪） | 02 方案 Q4 |

**这就是「综合优化求解」的全部含义：不是引入求解器，而是把每个手调量换成对应约束的有原则估计量，让同一个 argmin 框架承载所有目标。** 红线不变：不引 LP/MIP 求解器（OmniRouter 对偶迭代不保证可行解的限定反而支持这个选择——自己写可行性恢复比引依赖更可控）。

#### O1 对偶 λ 控制律：落地级规格（伪代码 + 参数表，全部 D 级工程参数、影子期标定）

```text
状态：λ1 ∈ [0, λ_max]，初始 = 当前 tier 倍率的等效值（零行为切换上线）
每个更新周期 T（先到者：1 小时 或 50 请求）：
    e = (T 内实际消耗 − T 内目标消耗) / T 内目标消耗     # 目标 = 剩余月预算 / 剩余周期数
    λ1 ← clamp(λ1 + η·tanh(e), 0, λ_max)                # tanh 饱和防脉冲，e=±1 处进入饱和
    λ̄ = 0.7·λ̄ + 0.3·λ1                                  # EMA 平滑后才进 score_all
score_all 接线：cost 项的乘子从 tier_cost_multiplier（router.rs:221-228）换为 λ̄ 的归一值；
    throttle/tight 阶梯保留为上限护栏（λ 失效时的 belt-and-suspenders），protect 档不动（红线）。
验收 = 闭环仿真：注入 2× 超支脉冲 → λ 上升 → 30 周期内消耗回落至目标带、全程无振荡；
    低流量场景（T=1h 内 <10 请求）单独仿真（放宽 e 的更新门限，避免噪声驱动）。
参数表：η=0.1 · λ_max=3×初始值 · 周期=1h/50 请求 · EMA α=0.3 · tanh 饱和 ±1 —— 全部 D 级，标注「工程自创」。
```

> 理论注记：该控制律 = 拉格朗日对偶的一阶在线近似（在线凸优化框架下的 dual ascent + 限幅滤波）；「为什么它比阶梯倍率稳」可被解释（连续饱和增益 vs 不连续增益）而非断言——闭环仿真直接出图，B8/B9 验收协议复用。

### 2.2 缓存一致性为什么是「新约束」而不是「又一个加分项」

sticky_bonus 把缓存当成「模型 m 的固有优点加分」；形式化之后它的真实身份是**状态依赖的切换成本**：`C(a_t)` 依赖上一步动作 `a_{t-1}`（`SL(a_{t-1}→a_t)`）——这使问题从「独立同分布的 per-request 优化」变成**有限状态马尔可夫决策（MDP）**。三层递进：

1. **贪心近似（现状+01 方案）**：每步 `argmax(… − μ·SL(m_prev→m))`，即把状态当成常数处理——一阶近似，工程上够用，**理论叙事上可以诚实表述为 "myopic policy for a switching-cost MDP"**；
2. **会话窗口联合优化（远期）**：plan-wave（波次内 N×M 联合分配）+ WISERouter 预算摊销同构——把窗口内的 SL 项联合最小化；
3. **RL（B10 触发，不承诺）**：见 §五。

**形式化对象表（论文/申报书可直接引用的精确定义）**：

```text
M = (S, A, P, R, C, β)
  S：会话状态 = {prefix_tokens, prev_model, last_active, 预算剩余比, 信号集(complexity/stability/domain)}
  A：门槛过滤后的候选模型集（health≠down ∧ tier≥band ∧ est_cost≤max_cost）
  P：未知且非平稳（模型升级/调价）——只能采样，不能假设先验
  R：质量，部分反馈（仅观测被选 arm）
  C：(账单成本, 切换损失 SL, 延迟)，可观测但缓存分量含 provider 侧随机性
  β：预算 knapsack + 供应商容量（RPM/TPM）
现状策略 = 对偶贪心（myopic policy）；SL 项使 C 依赖前一步动作 ⇒ switching-cost bandit；
理论工作面 = ①离线策略评估（doubly robust，前提 = propensity 日志完备，C10）②保守策略迭代（B10 触发后）。
```

### 2.3 三时间尺度架构（最终版 §三 的「分层」在统一形式化下的位置）

| 尺度 | 决策 | 载体 | 对偶量更新频率 |
|---|---|---|---|

## 四、「上升思想理论」：不训练 RL 的前提下，理论怎么讲才既漂亮又诚实

手记想「上升思想理论（强化学习/…）」。诚实边界（继承红线「不承诺最优」）之上，有三层理论包装**全部有文献支撑且与代码一致**：

### 4.1 第一层：约束 bandit / 在线优化形式化（现在就能写）

- LLooM 的路由 = **contextual bandit with knapsack & switching costs**：arm = 候选模型，context = 信号集（复杂度/会话/预算档/前缀稳定性），reward = 质量，resource consumption = 成本（knapsack 约束），且 reward 只有被选 arm 的观测（**partial feedback**）。
- 文献对位：预算约束 bandit（PILOT 的在线背包）、部分反馈下的反事实评估（Causal LLM Routing 的 doubly robust：结果回归与倾向概率二者之一准确即一致）、切换成本 bandit（StageRoute 部署层 UCB 的近似族）。
- **关键诚实点**：现在的确定性 argmin 没有随机化 → 选择概率恒 0/1 → **doubly robust 的前提（每候选非零选择概率）不满足**——这正是 05 §五 C10「propensity 日志（selection_probability / policy_mode）」是 P0 的理论理由：**没有 propensity 字段，未来一切反事实评估与理论叙事都不可信**。理论不是装饰，它规定了必须先补什么数据。

### 4.2 第二层：对偶分解与控制论解释（O1 落地时写）

- 预算控制器 = 拉格朗日对偶的在线一阶近似 = **PI 控制器**（tanh 限幅 + EMA + λ_max 的每个组件都有控制论对应：执行器限幅/滤波/执行边界）。
- 「为什么手调倍率会震荡、对偶 λ 不会」可以被解释而不是被断言：阶梯倍率是不连续增益，tanh 律是饱和连续增益——闭环仿真直接展示（B8/B9 验收协议现成）。

### 4.3 第三层：强化学习——什么时候、学什么、怎么讲（B10 触发）

- **触发条件（维持台账 B10）**：影子数据千级样本。单用户流量 ≈ 60-100 天/300 样本 → 千级 ≈ 1-2 年或代理流量起量；**所以论文叙事必须写成「条件触发的演进路线」而非承诺**。
- 触发后学什么：不是端到端 RLHF 式训练（Rust 单一决策真源红线 + 数据量不支持），而是**策略改进**两件具体的事：① 用离线回放（AIQ 多曲线 + 倾向加权）对 π 做保守策略迭代（EWMA 权重 → 学到的权重）；② 反事实评估替换 A/B（单流量不可 A/B，doubly robust 是唯一路径）。
- 论文表述模板：「我们将路由形式化为带切换成本的约束上下文 bandit；工程系统以对偶价格与置信半径实现其贪心近似；并在倾向日志完备后可进行离线策略评估与改进」——每半句都有对应代码或方案，评审追问任何一处都能落到锚点。

## 五、验收与风险

| 项 | 验收 |
|---|---|
| O1 对偶 λ | 闭环仿真收敛无振荡；分流率（norm_cost 相对中位数）可观测；低流量周期放宽不产生回摆 |
| UCB 替换 | 漂移场景（模型降价/升级）30 天窗口化后不再过度自信；n=0 乐观仅配额内 |
| propensity 日志 | 任何路由决策可回答「当时候选集是什么、各被选概率多少、哪个策略版本」——缺一即验收不过 |
| 理论叙事一致性 | 论文/申报书中的每个数学对象 ↔ 代码锚点一一对应（对偶 λ ↔ `tier_cost_multiplier` 替换处；UCB ↔ −0.3 替换处；SL ↔ sticky_bonus 替换处） |

| 风险 | 缓解 |
|---|---|
| 对偶 λ 在单用户低流量下更新过慢/过快 | η 自适应（流量低时放宽）；λ_max 封顶；闭环仿真覆盖低流量场景 |
| 理论包装过度被评审戳穿 | 全部按「有护栏的可解释启发式 / bandit 的贪心近似」措辞（红线 7），不写 "optimal"、"converges to optimal" |
| OmniRouter 命题 1 被误用为最优性保证 | 引用其限定（对偶迭代不保证可行整数解）；LLooM 的 fallback 链即可行性恢复的工程实现 |
| 千级样本长期不可达，B10 永远搁置 | 叙事不依赖 B10；4.3 的两件事在 propensity 完备后即可做离线部分（回放评估不需要千级，数百即可出第一版对比） |
